> Watches Certificate Transparency logs in real time and flags newly issued certificates that look like they are impersonating a domain on your watchlist. Speaks the raw CT wire protocol (RFC 6962) directly against public logs, no third-party CT client library, and scores each candidate domain against the official Unicode confusables table, not a hand-picked list of a dozen lookalike letters.

## Why watch Certificate Transparency

Every publicly trusted TLS certificate issued since 2018 gets logged to an append-only, publicly auditable Certificate Transparency log before a browser will trust it (mandatory since Chrome 68). That includes the certificates phishing sites use. A criminal registering `paypaI-secure-login.com` or a homoglyph like `pаypal.com` (Cyrillic а) still needs a certificate before the padlock shows up, and the moment a CA issues one, it lands in a CT log within the CA's maximum merge delay, almost always minutes.

That makes CT logs a genuinely useful early-warning feed: a brand can see a phishing certificate for a lookalike of its own domain before the site is fully built out, sometimes before the domain resolves to anything at all. Most tools that do this either poll `crt.sh` (a convenient index, but a third party in the loop, and rate-limited) or pull in a CT client library. glasswatch talks to the logs directly: `get-sth` and `get-entries` per RFC 6962 §4, decoding the `MerkleTreeLeaf` TLS structure by hand to pull the certificate back out.

## What glasswatch actually catches

Four separate impersonation patterns get scored per candidate domain, and a domain can trip more than one at once:

- **Homoglyph attacks** — `pаypal.com` with a Cyrillic а skeletonizes to the same string as `paypal.com` under a filtered version of [Unicode's official confusables table](https://www.unicode.org/Public/security/latest/confusables.txt) (1,515 entries that collapse to plain ASCII, regenerated by `scripts/build_confusables.py`).
- **Punycode / IDN homograph attacks** — the same check, but first decoding `xn--` labels back to Unicode with Python's stdlib `punycode` codec, since the wire format never shows you the Cyrillic character directly.
- **Typosquatting** — a label within edit distance 1-2 of the brand name (`acmeepay.com`, `gooogle.com`), via a from-scratch Levenshtein implementation.
- **Combosquatting and apex-prefix spoofing** — `acmepay-login-secure.net`, or the brand's whole domain used as the leading labels of someone else's domain (`acmepay.com.account-verify.net`), which is built specifically to fool address bars that truncate long URLs.

See [`glasswatch/detect.py`](./glasswatch/detect.py) for the exact scoring weights and [`learn/01-CONCEPTS.md`](./learn/01-CONCEPTS.md) for the theory behind each one.

## Honest positioning

Read this before trusting an alert or, worse, not trusting one.

**This is a detector, not a verdict.** A high score means "worth a human looking at," not "confirmed phishing." A company that legitimately owns both `acmepay.com` and `acmepay-support.net` will trip the combosquat rule on its own certificate. glasswatch has no way to know that without you telling it, which is what the watchlist is for.

**The apex-prefix and brand-substring rules are prefix-only, not a real public suffix list.** `acmepay.com` used as the *leading* labels of a longer domain is caught; `acmepay.com` embedded in the *middle* of one is not, and `core_name` is guessed by stripping the last DNS label, which is wrong for multi-part suffixes like `.co.uk` (set `core_name` explicitly in the watchlist for those). Both are documented shortcuts, not bugs; see `learn/04-CHALLENGES.md` for what closing them would take.

**STH signatures are not verified.** `stream` trusts the log's TLS certificate and the fact that its URL came from Google's curated, actively-maintained log list. That is the same trust model most CT monitors use day to day; full gossip-audit verification is out of scope here, and is called out as an extension exercise instead of quietly skipped.

**One log at a time.** There is no single log that sees every certificate; `--log-url` picks one, or `stream` defaults to the first log Google's list reports as usable. Watching every currently-usable log at once is a straightforward extension (run one `stream` process per log against the same `--db`), just not the default, since a single log already produces a meaningful, demoable stream of real traffic.

## Quick Start

```bash
cd PROJECTS/advanced/ct-phish-hunter
python -m venv .venv && source .venv/bin/activate   # or .venv\Scripts\activate on Windows
pip install -e ".[dev]"

cp watchlist.example.yml watchlist.yml   # edit in your real brands/domains

# Offline: score a plain list of domains, no network required
glasswatch scan-file domains.txt --watchlist watchlist.yml --all

# List which CT logs are currently accepting submissions
glasswatch logs

# Live: poll a log, backfill the last 500 entries, then keep watching for 2 minutes
glasswatch stream --watchlist watchlist.yml --db findings.db --backfill 500 --seconds 120

# Read-only dashboard over whatever findings.db has collected
glasswatch serve --db findings.db --port 8787
```

`scan-file` needs no network at all, which makes it the fastest way to see the detection engine work. Running it against `watchlist.example.yml` (brands: `acmebank.example`, `acmecloud.example`, `shopwave.co.example`) and a short mixed list of legitimate and suspicious domains:

```bash
cat <<'EOF' > domains.txt
acmebank.example
login.acmebank.example
acmebank-secure-login.net
xn--cmebank-1fg.example
acmebank.example.verify-account.net
totally-unrelated-domain.test
EOF
glasswatch scan-file domains.txt --watchlist watchlist.example.yml --all
```

```
[  MEDIUM] score=25  acmebank-secure-login.net  (brand: acmebank.example)
    - combosquat:acmebank-secure-login:login+secure
[CRITICAL] score=75  xn--cmebank-1fg.example  (brand: acmebank.example)
    - homoglyph-exact:xn--cmebank-1fg
    - punycode-encoded
[    HIGH] score=55  acmebank.example.verify-account.net  (brand: acmebank.example)
    - apex-domain-as-prefix:acmebank.example

scanned 6 domains, 3 findings
```

The two legitimate domains (`acmebank.example` itself and its real subdomain) and the unrelated one produce no output at all, which is the point: a real watchlist run against real CT traffic should be quiet almost all the time.

## Architecture

```
                 ct/v1/get-sth, ct/v1/get-entries (RFC 6962)
                              |
                              v
 log_list.json  ------>  ctlog.py  ------>  detect.py  ------>  store.py (SQLite)
 (usable logs)     MerkleTreeLeaf         confusables +              |
                    -> DER cert           levenshtein +              v
                    -> SAN domains        combosquat scoring     server.py
                                                                  (localhost dashboard)
```

- **`ctlog.py`** — the RFC 6962 client. Discovers usable logs from Google's log list, fetches `get-sth`/`get-entries`, and hand-decodes the `MerkleTreeLeaf` and `PrecertChainEntry` TLS structures to recover a `cryptography.x509.Certificate` from every leaf, precerts included.
- **`confusables.py`** + **`confusables_data.py`** — punycode decoding and the ASCII skeleton function, backed by a generated (not hand-typed) subset of Unicode's confusables table.
- **`detect.py`** — pure functions, zero network or disk I/O, scoring one domain against one brand. This is the part with the heaviest test coverage on purpose.
- **`watchlist.py`** — loads the brands to protect from YAML.
- **`store.py`** — SQLite, dedupes findings on `(domain, brand)`, tracks `seen_count`.
- **`cli.py`** / **`server.py`** — the four subcommands and a stdlib-only (no framework) read-only dashboard.

## Security considerations

- The dashboard renders attacker-controlled strings (certificate domain names). Every value is passed through `html.escape()` before it reaches the response; see the comment at the top of [`glasswatch/server.py`](./glasswatch/server.py). Skipping that step would turn a phishing detector into a stored-XSS delivery mechanism.
- `serve` binds to `127.0.0.1` by default. It is a read-only view with no authentication, so do not point `--host` at `0.0.0.0` on a shared or internet-facing machine without putting something in front of it.
- No secrets, API keys, or credentials are used anywhere in this project; every endpoint it talks to (`gstatic.com`, the CT logs themselves) is public and unauthenticated.
- Findings are a *lead*, not evidence of a crime. Do not take unilateral action (takedown requests, blocklisting, contacting a registrar) against a flagged domain without a human review; typosquat and combosquat rules both have plausible, legitimate false-positive cases (a brand's own marketing domains, a reseller, a coincidence).

## Testing

```bash
pytest                     # 39 tests: detection scoring, RFC 6962 leaf parsing against
                            # real captured CT log entries, SQLite dedup, watchlist loading
pytest --cov=glasswatch    # with coverage
```

`tests/fixtures/sample_leaves.json` holds two real entries (one `x509_entry`, one `precert_entry`) captured live from Cloudflare's Nimbus2026 log, so the RFC 6962 parsing tests never depend on the network or on a specific log index still existing later.
